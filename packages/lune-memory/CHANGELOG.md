# Changelog

All notable changes follow [Keep a Changelog](https://keepachangelog.com/en/1.0.0/).

## [Unreleased]

### Added

- **Session import.** Import the session files of Pi, Claude Code and Codex into one SQLite database with full-text search, and write a Markdown transcript of each session. Each harness is off until `lune-memory setup <harness>` turns it on. The import reads only new or changed files and follows a link only inside the harness folder, and a file in an unknown format, or with a text block of an unknown shape, fails alone while its earlier events stay. Imported text and notes are stored without redaction until a setting for it exists, and only the error text of a failed import is redacted.
- **Projects across harnesses.** Map every session to the project of its repository. All worktrees of a clone and all clones that share a remote share one project, and a folder outside Git becomes a project with `register`. `rename`, `merge` and `split` correct the mapping, `split` takes along the items that only the moved sessions support and the provisional notes that they wrote, and the moved sessions go through Dreaming again.
- **Session summary (L1).** Give each new session a summary within 200 lines and 25 KB: global preferences, the project overview, the working state of the current branch, other active branches, the recent sessions that Dreaming has not processed and that fit the budget, and how to use the memory. Claude Code and Codex get it from a SessionStart hook that `setup --install-hook` adds. Pi gets it from the extension as a stable system prompt section.
- **Dreaming.** Update the memory in the background after a session is idle for `idleHours`. An Analyzer call for each session extracts decisions, lessons, preferences, the working state and open items with their evidence, an Organizer call for each project merges them into the items and the wiki, and a global pass keeps the preferences that apply in every project. The backend checks every change against its live evidence and the L1 budget, and retires the Working State and the open items of merged or deleted branches. Each project and the global pass commit in their own transaction, so one failure leaves the others committed. `dream` starts a pass at once, `runs` lists passes and `revert` undoes one, with `--reprocess` to analyze its sessions again.
- **Models through pi-ai.** Call the Dreaming model through pi-ai, so every provider and model that pi-ai knows works without a separate adapter. A key in the credential store has priority over the environment variable of the provider, and no list or API response shows a stored key.
- **MCP tools.** `lune-memory mcp` serves `transcript_search`, `note_write`, `note_update`, `note_retract` and `memory_location` over stdio. The Pi extension registers the same tools and fills in the session and the folder. A note stays provisional until a Dreaming pass finds evidence that supports it.
- **Markdown views.** Write the project index, the wiki, the notes, the transcript links and Global Memory as read-only Markdown under `~/.lune-memory/views`. Each change writes a new generation and moves the link, and earlier generations stay for restore. When a view write fails, the change stays in the database, `status` shows the error, and the daemon writes the views again after its next import.
- **Local daemon and settings page.** Run imports and scheduled passes in a daemon that listens on loopback only and needs a random token for every request. `lune-memory settings` opens a local page where you turn harnesses on, select the model and its limits, store API keys, start and revert passes and manage projects.
- **Command line.** `lune-memory` covers setup, search, import, Dreaming, runs, sessions, projects, config, credentials, the daemon and the hooks. It calls the daemon when it runs and opens the database itself when it does not. `--home` can come before the command, and `dream --project _unassigned` covers the sessions outside any project.
- **Forget and retention.** `forget` deletes one session and the memory that only it supports, and keeps its file from a new import. `retentionDays` deletes older sessions, events and transcripts and keeps the items.
- **Web logs.** The settings page's Logs section shows recent daemon output with time, severity and source badges, and updates while open. File import failures record their paths and reasons in the same log.
- **Custom providers.** Add endpoints for OpenAI Chat Completions, OpenAI Responses or Anthropic Messages through the settings page, `provider add|list|scan|remove` commands or local API, and scan their models. Configuration uses Pi's `models.json` format, keys stay in `credentials.json`, and pi-ai sends the requests. Resolved keys and headers are validated before requests without exposing their values in errors. Calls reject redirects, and an unreadable configuration stops Dreaming to prevent sending sessions to the wrong endpoint.
- **Model picker.** Choose the Dreaming model in a dialog with a search box and one list of models for each provider, instead of one drop-down with every model of every provider. Providers with a key come first.

### Changed

- **BREAKING: `GET /api/providers` returns `{ providers, error }`.** The list was a bare array. `error` says why `models.json` did not load, and each provider has `custom`, `api` and `baseUrl`, and each model its `contextWindow`. A client of the old shape must read `providers`.
- **Setup prints sandbox access.** `setup claude` and `setup codex` print how a sandboxed session reads the memory files: the Read rule for Claude Code, and the views folder for a Codex sandbox that limits reads. Setup does not change a permission setting.
- **Over-budget summary.** When the stable part of a project's summary is over its budget, Dreaming asks the Organizer to shorten it, even with no new sessions, for at most `maxAttempts` passes in a row. A manual pass ignores the limit.
- **Model judgment for preferences.** Let the Dreaming models decide generality, withdrawal and preference matching from evidence and context. Remove the backend's semantic keyword lists, negation patterns and word matching; retain source, citation, scope and revision validation. When global preferences exist, new trusted user statements from eligible sessions outside a project reach the global model for review.

### Fixed

- **Evidence and review consistency.** Fix existing source evidence before analysis, including missing sources and global Notes, and require evidence from each Note review. Review deleted citations across project and global scopes, preserve Note review after registration, reject results whose project ownership changed, and retry global promotions rejected for stale evidence. Project extraction and global promotion now keep separate idempotency ownership.
- **Claude compaction with a preserved segment.** Import Claude Code sessions whose compaction keeps a segment of recent messages. The parent chain of such a session formed a loop and the whole file failed to import.
- **Global pass retries.** Stop a failing global pass after `maxAttempts` failures in a row, until a project preference changes or new results arrive. A manual pass ignores the limit.
- **Native session provenance and history.** Recognize quoted memory paths and Claude shell reads, and preserve earlier evidence when unknown text or tool-result content fails import. Honor Codex injected-instruction and subagent markers, restore Claude compaction's preserved context, and roll back Codex tasks as complete turns.
- **Retry failed imports.** Retry files with an import error on the next scan even when their size, modification time and content are unchanged. Sessions can recover after a parser fix without editing their native files.
