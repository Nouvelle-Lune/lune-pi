# Changelog

All notable changes follow [Keep a Changelog](https://keepachangelog.com/en/1.0.0/).

## [Unreleased]

### Added

- **Allowed subagent models.** Select multiple models from Pi's scoped models under `/lune-core-settings subagents`. A nonempty selection replaces the session's default allowed list for new runs, including explicit models and auto tiers; clear it to restore Pi's scope. Changes update the tool's model options immediately, without changing existing runs or main-model inheritance.
- **Subagent runs.** The main agent delegates a task with `subagent_start` and continues while the run works in its own Pi session with a fresh context. With `tasks`, one call starts several runs at the same time, and an entry that fails to start does not stop the others. `subagent_send`, `subagent_status` and `subagent_stop` steer, read and stop runs, and each ended turn reaches the main agent as a batched steer message with the run's report. When a message continues a turn after its report, the earlier reports reach the main agent with the turn's last report. Each report message is confirmed in the main session and sent again when it is missing; after you interrupt the main agent, it goes with your next message.
- **Run titles.** An optional `title` on `subagent_start` labels a run in the `/agents` inspector, the Dock and its end-of-turn notice. The subagent tools still take a run's ID, never its title or name, and the results and notices name the run only by that ID; passing a title or name fails, and the error lists the branch's run IDs.
- **Agent definitions.** Markdown files in `lune-subagents/` in Pi's agent directory, and in `.pi/lune-subagents/` of a trusted project, define reusable roles with their tools, model, thinking level and isolation. A project definition replaces a user definition of the same name. The loaded agents appear in the system prompt's `subagents` section, with project agents marked, and invalid or replaced files are reported instead of loaded.
- **Runs per branch and session.** A run belongs to the branch that started it, and its reports wait while another branch is active, then arrive when you return. Leaving a branch with running runs asks once whether to keep or stop them, and the Dock counts kept runs while they work. Runs come back from their own session files when you resume the session, and runs that arrive through `/fork` or `/clone` are read-only.
- **Extension tools in runs.** A run can select a tool that one of your user or project extensions registers. The run loads that extension in its own session with only the selected tools, also on resume. Names that runs have on their own stay Pi's, the subagent tools stay unavailable, and an extension that fails to load or does not register the tool fails the start.
- **Worktree isolation.** A run can work in its own detached Git worktree at the current `HEAD` commit. The package keeps the worktree for later turns and never merges or deletes it.
- **Dock entry and `/agents` inspector.** The Dock counts runs by status, and its full level names the run that changed last. Without runs it shows only `○ Agents` at every display level, matching Shell and Ask. A narrow Dock cell leaves out complete parts, the least urgent first, and never cuts the line. A failed or blocked turn shows a red `✕` for 10 seconds, or until you open the run in the inspector; then a gray `●` remains. The inspector shows each run's live transcript as a compact log, with one row per tool call and per finished thought and a report call marked `writing` until the run records it, and the model and thinking level that its requests use. It lets you write to a run or stop it, and shows its start values, workspace and token usage.
- **Built-in definition-creation skill.** `create-lune-subagent` asks for the global or project scope, name, description and model, then recommends thinking, tools, isolation and role instructions for the task. It saves only the definition and destination you approve, without starting a run.
- **Auto model.** `model: auto` in `subagent_start` or a definition lets a Pi classifier rate the task's tier. The run uses the model set for that tier, or for the next tier up that has one, with the main agent's model as the ceiling. When the call and the definition set no thinking level, the classifier also rates the thinking among the levels that Pi reports for the run's model, in the same request when the possible models support the same levels and in a second request otherwise. A separate high-risk question asks whether a mistake in the task could seriously harm security, privacy, data, money or production; at the configured threshold, the model comes from at least the configured floor tier, while the rated tier stays as it is. An unsure answer moves one level up. A long task and the agent's instructions are cut in the middle so that the request fits the classifier's context window, counted in UTF-8 bytes. When the classifier fails, the run uses the main agent's model and thinking, and the start values and the inspector show the error. Without a selected classifier, auto runs use the main agent's model and thinking. The start values show the rating, and the inspector shows it in the model row and at the top of the run's log.
- **Subagents settings.** `/lune-core-settings subagents` selects the auto classifier, its Auto tiers menu selects one model per task tier and the high-risk floor and threshold, and its Custom agents menu edits each definition's name, description, model, thinking, tools and isolation in its file. Start values apply to the next run; names and descriptions apply after `/reload`.
- **Auto mode only.** A Subagents setting that removes the `model` parameter from `subagent_start`, so every inline run uses `model: auto` and the main agent cannot pick a model. An inline call that still names another model starts nothing. Custom agents keep their definition's model.
- **Startup agent list.** When Lune Core Theme is enabled, the session's loaded agent names appear under `[Agents]` below Pi's other startup resources. The list uses the same validated, trusted-scope definitions as the tools and prompt, and refreshes with the session.

### Changed

- **Package presentation.** Introduce the package with native Pi screenshots, installation steps and a shorter feature guide. Keep detailed contracts in a bundled reference, and declare the package image and public npm access for its first release.
- **Core dependency.** Require `@lune_99/pi-lune-extensions-core@^0.2.0` for the Auto tiers and Custom agents menus. Publish Core 0.2.0 before Subagent so registry installations receive the required Panel API.
- **Delegation guidance.** Clarify delegation boundaries, task context, editing ownership and minimal tool selection. Prompt agents to return concise evidence-backed reports and validate results before integration.
- **Agent runs keep their definition.** A `subagent_start` call that names an agent takes only `task` and `title`, and the definition's model, thinking, tools and isolation always apply. A call that also sets one of them starts nothing, and in a `tasks` call no entry starts. Edit the definition to change a role's settings.
